# lean-team — экономная работа с субагентами в Claude Code

[English version](README.md)

Навык (skill) и два профиля субагентов, которые превращают Claude Code в «команду»: дорогая модель планирует, решает и проверяет, а объём работы делают более дешёвые исполнители. Работа сначала уходит **внешним CLI-исполнителям** (Codex CLI, Antigravity CLI или любой CLI, для которого вы напишете адаптер), то есть идёт на лимитах ваших других подписок. Когда их лимиты кончаются, подключаются собственные уровни Claude — Sonnet и Haiku. Встроенный цикл обучения превращает повторяющийся измеренный опыт в правила; один удачный запуск правилом не становится.

## Что внутри

| Путь | Что это |
|---|---|
| `skills/lean-team/SKILL.md` | **Универсальное ядро** (читается при каждом вызове, поэтому короткое): бриф один раз в файл, роли и порядок делегирования, параллельные агенты с владением файлами, проверка одной командой, жёсткие лимиты, бюджет лимитов, отчёт по итерации, цикл обучения |
| `skills/lean-team/adapters/` | По файлу на каждого внешнего исполнителя, читается только когда он нужен: `codex.md`, `antigravity.md` и `TEMPLATE.md` для своего (DeepSeek, Gemini CLI, Aider и т. д.) |
| `skills/lean-team/recipes/` | Особенности стеков и платформ, читаются только когда подходят: `web-js.md`, `windows.md` |
| `skills/lean-team/templates/` | Вопросы ретро, формат правила-кандидата, формат строки метрик |
| `agents/lean-builder.md`, `agents/lean-worker.md` | Запасные уровни Claude: строитель на **Sonnet** (пишет код и сам проверяет), исполнитель на **Haiku** (поиск, скачивания, контент, настройка, механика) |
| `docs/evidence.md` | Замеры, на которых держатся правила, и открытые правила-кандидаты |

## Установка

### Вариант А — плагином прямо из GitHub (удобно обновлять)
В Claude Code:
```
/plugin marketplace add dmtrml/claude-lean-team
/plugin install lean-team@claude-lean-team
```
При установке плагином агенты могут называться с префиксом: `lean-team:lean-worker`, `lean-team:lean-builder`.

### Вариант Б — скопировать файлы скриптом
```bash
git clone https://github.com/dmtrml/claude-lean-team.git
cd claude-lean-team
./install.sh                      # для всех проектов (~/.claude)
./install.sh /path/to/project     # только для одного проекта (<проект>/.claude)
```
Windows PowerShell:
```powershell
.\install.ps1                              # для всех проектов
.\install.ps1 -Project C:\path\to\project  # только для одного проекта
```
Вариант «для проекта» удобно закоммитить в репозиторий проекта — тогда навык будет у всей команды. После установки начните **новую сессию** Claude Code.

## Использование
Напишите задачу и добавьте `/lean-team` — или просто «экономь токены». Пока навык не вызван, он почти ничего не стоит (в контексте только строка описания).

Внешние исполнители необязательны. Если ни один адаптер не установлен и не залогинен, всё работает на уровнях Claude. Чтобы подключить Codex CLI или Antigravity CLI, установите их и выполните вход; адаптеры описывают запуск без диалога, права, чтение токенов и лимитов, продолжение разговора и переход на Claude.

## Слои: общее ядро и ваш собственный опыт
- **Ядро** (этот репозиторий): универсальные правила. Автоматически не меняется; изменения приходят pull request'ами с доказательствами.
- **Личный слой** `~/.claude/lean-team/local.md` и **слой проекта** `<проект>/.claude/lean-team.md`: правила, которые агент выучил для вас и вашего проекта. Их ведёт сам агент; они лежат вне папки плагина (обновление плагина её перезаписывает) и сюда не коммитятся.
- **Записи** `~/.claude/lean-team/metrics.jsonl` и `candidates.md`: строка метрик на каждую итерацию и правила-кандидаты на проверке.

## Как навык улучшается
Помимо самой задачи агент смотрит, как её можно было сделать дешевле по токенам или лучше по результату, и по ходу работы отмечает потери (лишние раунды ревью, переделки, повторное чтение, неудачные делегирования, исправления от пользователя). После каждой итерации он пишет строку метрик, отвечает на короткое ретро и записывает каждую идею как правило-кандидат с ожидаемым эффектом — до следующей задачи — и показывает новых кандидатов в отчёте, чтобы вы могли их отклонить. Затем кандидаты проверяются на следующих реальных задачах, без отдельных тестовых прогонов. Кандидат становится правилом, когда целевая метрика сдвинулась в ожидаемую сторону без потери качества: один замер для механического эффекта (например, меньше вывода), два сравнимых шага для большого (в 2 раза и больше), три для маленького. В ядро правило предлагается, только когда подтвердилось в 2 проектах. Подробно: `SKILL.md` §8.

## Участие
Pull request'ы приветствуются, особенно новые адаптеры (из `adapters/TEMPLATE.md`, заполненные по маленькому пробному запуску) и доказательства. Изменение правила требует таблицы доказательств: где применяли, метрика до и после, сохранилось ли качество.
